# Тест-драйв тариф: ограничение по времени (3 дня) + уведомление об окончании

Дата: 2026-09-14
Статус: утверждено, готово к реализации

## Контекст

Сейчас после регистрации пользователь получает демо-режим: `users.free_contacts = 3`
(миграция `2025_04_30_115005_add_column_free_contacts_to_users.php`). Пока счётчик не
обнулился, можно открыть 3 любых контакта (билдеров или проектировщиков — единый пул,
см. `App\Services\Tariff::freeContactsMinus()`), и они остаются доступны навсегда
(`UserOpenContact`). Каталоги («Строительство» и «Проектирование») доступны любому
авторизованному пользователю без проверки тарифа — ограничение действует только на
открытие карточки с контактом (`Tariff::checkContactAccess()`).

Проблема: срок в «3 дня», который сейчас упоминается только в маркетинговых текстах
(`resources/views/pages/index.blade.php`, `components/modals.blade.php`), нигде не
считается и не проверяется. Демо-доступ по факту не ограничен по времени — только по
количеству открытых контактов. Также отсутствует поле с датой первого входа (нужно
для отсчёта триала и для будущей статистики) и отсутствует любое уведомление о том,
что демо-период закончился.

## Требования (из задачи)

1. Тест-драйв — 3 дня с момента регистрации/первого входа. В этот период доступны все
   разделы (строители и проектировщики) и открытие 3 любых контактов, которые остаются
   доступны навсегда.
2. После окончания тест-драйва при входе в систему должно показываться сообщение о том,
   что тест-драйв закончился, с предложением оплатить тариф на главной странице или в
   личном кабинете. Сообщение — в стилистике главной страницы Radarium.

## Решения по неоднозначностям (согласовано с заказчиком)

- Точка отсчёта триала — **первый вход в систему** (не `created_at`), т.к. отдельное
  поле даты первого входа нужно в любом случае для будущей статистики. Хранится отдельно
  от `last_login_at`, которое перезаписывается при каждом входе.
- По истечении 3 дней бесплатные контакты **сгорают полностью**, даже если из трёх
  использован не весь лимит.
- Просмотр каталогов (списки/карточки без открытия контакта) остаётся **всегда открытым**
  всем авторизованным пользователям — как сейчас. Ограничивается только открытие *новых*
  бесплатных контактов.
- Уведомление — **модальное окно** в стиле главной страницы, всплывает автоматически на
  любой странице сразу после входа (а не только на дашборде), пока пользователь не купит
  тариф. Модалку можно закрыть крестиком/кнопкой «Закрыть» без обязательного перехода по
  ссылкам «Тарифы» / «Личный кабинет» — это лишь предлагаемые действия, не блокирующие.

## Выбранный подход

Вариант A — доработка существующего механизма `free_contacts`, без изменения архитектуры
платных тарифов (`user_tariffs`, `PaymentTariff`, `UserTariffObserver`, Robokassa не
затрагиваются). Альтернатива (создание отдельного системного `payment_tariffs` тарифа
«Тест-Драйв» с записью в `user_tariffs`) была рассмотрена и отклонена как более рискованная
для продакшена с реальными платящими пользователями — оставлена как возможный будущий
рефакторинг.

## Архитектура и компоненты

| Компонент | Изменение |
|---|---|
| Миграция `users` | + `first_login_at` (nullable timestamp) |
| Миграция-бэкофилл | Для существующих строк: `first_login_at = COALESCE(first_login_at, created_at)` — не продлевает и не обнуляет уже истёкший/текущий триал задним числом |
| `App\Models\User` | Константа `TRIAL_DAYS = 3`; методы `getTrialEndsAt(): ?Carbon`, `isTrialActive(): bool`, `isTrialExpired(): bool`, `hasActivePaidTariff(): bool` (обёртка над `getFirstActiveTariff()`); правка `getLeftContacts()` — в демо-ветке `days_left` и `count_contacts_left` считаются с учётом `isTrialExpired()`, а не хардкод `30` |
| `App\Providers\AppServiceProvider` | В существующем листенере `Login`: один раз проставить `first_login_at`, если он ещё `null` (в т.ч. срабатывает при `Auth::login()` в `RegisteredUserController` — то есть практически сразу при регистрации); если триал истёк и нет активного платного тарифа — `session()->flash('show_trial_expired_modal', true)` |
| `App\Services\Tariff` | `checkAccessToOpen()`, `checkContactAccess()`, `freeContactsMinus()` — бесплатные контакты пригодны только пока `!$user->isTrialExpired()`. Доступ к уже открытым ранее контактам (`getOpenContactLog`) не меняется — проверяется раньше и не зависит от триала |
| `resources/views/components/modals.blade.php` | Новая модалка `rd-trial-expired`, стилистика как у `rd-testdrive-auth`/`rd-tarif-todo` (`modal fade modal-registr modal-centered`, `tarif-name`, `btn-color`, `box-btn-line`). Кнопка закрытия (`btn-close`, `data-bs-dismiss="modal"`) — без обязательного перехода. Дополнительно кнопки-ссылки «Выбрать тариф» → `{{ route('index') }}#buy_tariff`, «Личный кабинет» → `{{ route('profile.edit') }}` |
| JS (инлайн в `x-modals` либо `v2/js/script.js`) | Если в сессии есть флеш `show_trial_expired_modal` — автоматически открыть `#rd-trial-expired` через Bootstrap JS Modal API при загрузке страницы |

Оба layout'а (`layouts/global.blade.php`, `layouts/landing.blade.php`) уже подключают
`<x-modals :$userRoleList />` и общий `v2/css/styles.css`, поэтому новая модалка будет
выглядеть одинаково на любой странице без дублирования разметки.

## Поток данных

1. Регистрация → `Auth::login()` → событие `Login` → `first_login_at` = сейчас (было
   `null`). Это старт тест-драйва.
2. Любой следующий вход → `last_login_at` обновляется всегда; `first_login_at` больше не
   трогается.
3. При каждом входе: если активного платного тарифа нет и `now() >= first_login_at + 3
   дня` → выставляется флеш-флаг `show_trial_expired_modal`.
4. На первой отрисованной после логина странице (любой layout) модалка открывается
   автоматически; пользователь может закрыть её и продолжить пользоваться каталогом.
5. Попытка открыть новый контакт (`Tariff::checkAccessToOpen()`) — если триал истёк,
   `free_contacts` больше не работает, даже если остаток `> 0`.
6. Уже открытые ранее контакты остаются доступны навсегда — без изменений.

## Граничные случаи

- `first_login_at = null` для залогиненного пользователя — по факту невозможно (Login
  уже случился бы), но код не должен падать: трактуется как «триал ещё не начался», доступ
  не блокируется.
- Активный платный тариф есть — модалка не показывается вообще, независимо от статуса
  триала.
- Все 3 контакта потрачены раньше 3 дней — уже работает сегодня (`free_contacts = 0`);
  новое условие по времени — дополнительный, а не заменяющий барьер.
- Модалка показывается **при каждом входе**, пока не куплен тариф, но не мешает работе —
  свободно закрывается.

## Тестирование

- Unit: `User::isTrialExpired()/isTrialActive()/getTrialEndsAt()` на разных значениях
  `first_login_at` и текущего времени.
- Unit/Feature: `Tariff::checkAccessToOpen()`/`checkContactAccess()` — блокируют новые
  бесплатные контакты после истечения триала; не блокируют доступ к уже открытым.
- Feature: логин после истечения триала → в HTML-ответе есть модалка `rd-trial-expired`
  (и на странице каталога, и в личном кабинете); логин с активным платным тарифом →
  модалки нет.
- Тест на бэкофилл-миграцию: у существующих пользователей `first_login_at` не затирает
  уже установленное значение и корректно проставляется от `created_at`, если было `null`.

## Не входит в объём этой задачи

- Замена `free_contacts` на полноценную запись в `user_tariffs` (Вариант B) — возможный
  будущий рефакторинг.
- Изменение доступа к просмотру каталогов — остаётся без изменений (всегда открыт).
